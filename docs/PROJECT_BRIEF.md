# Re:Start Quest MVP 브리프

## 이번 테스트의 목적

AgentFlow가 하나의 구현 요청을 받아 기존 저장소 조사, 팀 내 설계 합의, 작업 분할, 병렬 구현, QA, 리뷰, 결함 수정, 통합 PR 전달까지 수행하는지 확인한다.
제품은 이번 테스트에 한해 Re:Start Quest로 정한다. 실제 취업용 포트폴리오 주제 선정은 별도이며, 경쟁 서비스 조사나 다른 제품 제안으로 이 구현 요청을 대체하지 않는다.

## 대상과 문제

취업 준비를 오래 쉬었거나 계획을 실행하지 못한 사람이 실패 후에도 더 작은 구직 행동으로 돌아오도록 돕는다.
취업 정보 모음이나 사용자의 의지를 평가하는 서비스가 아니다.

## 핵심 흐름

```text
사용 가능한 시간과 현재 상태 입력
-> 오늘 실행할 작은 구직 퀘스트 생성
-> 완료 또는 실패 기록
-> 실패 이유에 맞춰 더 쉬운 퀘스트 제안
-> 새 행동 실행
-> 대시보드에서 실제 실행 기록과 다음 행동 확인
```

## MVP 범위

1. 사용자의 시간과 상태를 받아 실행 가능한 오늘의 퀘스트를 생성한다.
2. 완료 처리와 실패 이유 입력을 지원한다. 실패는 비난하지 않고 다음 행동을 찾는 입력으로 사용한다.
3. 실패 이유에 맞춰 시간, 난이도 또는 행동 범위를 줄인 대안을 제공한다. 원래 퀘스트와 재설계 이력의 관계를 보존한다.
4. 대시보드는 실제 저장된 퀘스트, 완료, 실패, 재설계 기록을 반영한다.
5. 프론트 화면, 백엔드 API, 영속 저장을 실제로 연결한다. 새로고침과 서비스 재시작 뒤에도 확정된 기록이 남는다.

유료 외부 AI 서비스나 실제 채용 공고 연결을 필수 전제로 삼지 않는다. 규칙 기반 생성으로도 핵심 흐름은 실행할 수 있어야 하며, AI를 추가하면 사용 여부와 실패 시 동작을 명시한다. UI mock과 하드코딩된 대시보드를 실제 연동 결과로 보고하지 않는다.

## 팀이 결정할 내용

- 기술 스택, 데이터 모델, API 계약, 화면 구조, 테스트와 로컬 실행 방식.
- 한 번에 처리할 수 있는 작업 범위, 의존 관계와 안전하게 병렬화할 부분.
- 구현 중 발견한 문제와 대안. 팀원이 이견을 보고하면 팀장이 판단하고 관련 설계를 함께 갱신한다.

작업 단계를 고정된 개수로 제한하지 않는다. QA와 리뷰의 실제 결함은 구현자에게 되돌리고 재검증한다. 정상적인 단계 진행은 매번 사용자에게 재개 지시를 요구하지 않는다. 권한, 비용, 외부 계정 또는 사용자 요구의 실질적인 충돌만 사람에게 확인한다.

## 완료 조건

- 깨끗한 환경에서 README의 명령으로 설치, 실행, 테스트할 수 있다. 비밀값 없는 설정 예제를 제공한다.
- 같은 통합 커밋에서 퀘스트 생성, 완료, 실패 이유 입력, 더 쉬운 퀘스트 재설계, 대시보드 반영을 실제 HTTP와 브라우저로 검증한다.
- 유효하지 않은 입력, 중복 완료나 실패 요청, API 오류 상황을 처리하고 관련 회귀 테스트를 남긴다.
- 저장된 이력이 새로고침과 재시작 후 유지된다. 테스트 자료와 실제 저장 결과를 구분한다.
- 데스크톱과 모바일 화면의 핵심 흐름을 확인하고 검증 증거를 남긴다.
- 설계, API, 구현, 실행 문서가 같은 동작을 설명하며, QA와 리뷰는 검증한 커밋과 실제 실행 결과를 제시한다.
- 팀장은 전체 MVP 구현 범위, PR, 실행 방법, 검증 결과, 알려진 제한을 한 번의 최종 보고로 종합한다. 일부 단계 완료나 검증 대기는 제품 완료가 아니다.

## 제외 범위

이력서 첨삭, 모의면접, 실제 채용 공고 수집, 정책 추천, 결제, 소셜 로그인, 정신건강 진단은 이번 MVP에 넣지 않는다.
외부 서버 배포, 운영 데이터 변경, 자동 머지는 별도 승인 대상이다. 실행하지 못한 CI나 자동 리뷰를 성공으로 표시하지 않는다.

## 문서와 기준선

제품 문서와 결정 기록은 이 저장소의 `docs/`에 남긴다. AgentFlow 내부 실행 로그를 제품 문서 대신 사용하지 않는다.
하나의 정본 설계에서 시작하고 필요한 계약 문서만 추가한다. 변경 이유와 현재 유효한 결론을 남기되 같은 내용을 역할마다 중복 문서로 늘리지 않는다.
과거 실험의 Task, 닫힌 PR, 브랜치, 후보 SHA, 백업 구현은 재사용하지 않는다. 이번 main에서 새로 생성한 설계와 코드만 누적한다.
