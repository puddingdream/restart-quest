# 프로젝트 브리프

## 목적

AgentFlow가 실제 팀처럼 제품을 조사하고, 설계하고, 병렬 구현하고, 검증하고, 릴리스 후보까지 완주할 수 있는지 확인한다. 결과물은 취업용 포트폴리오로 설명할 수 있을 만큼 문제 정의와 기술적 깊이가 분명해야 한다.

## 보존할 문제 인식

초기 아이디어인 Re:Start Quest는 취업 공백자가 실패 후에도 더 작은 행동으로 다시 시작하도록 돕는 구직 행동 재진입 엔진이었다. 단순 취업 정보 모음이나 이력서 생성기가 아니라 다음 흐름을 핵심으로 삼았다.

```text
현재 상태 파악
-> 오늘 실행할 작은 행동 제안
-> 실패 이유 기록
-> 더 쉬운 행동으로 재설계
-> 실행 기록과 다음 행동 연결
```

이 문제 인식은 참고할 가치가 있지만, 제품 주제는 확정되지 않았다. 비슷한 취업 도구가 많아 포트폴리오 차별성이 부족할 수 있으므로 새 작업은 경쟁 서비스 조사와 대안 아이디어 비교부터 시작한다.

## 새 제품 선정 기준

- 실제 사용자가 겪는 구체적인 반복 문제를 해결하는가
- 기존 서비스와 다른 핵심 상호작용을 한 문장으로 설명할 수 있는가
- 단순 LLM 포장이나 기능 모음이 아닌 도메인 모델과 상태 변화가 있는가
- 프론트엔드, 백엔드, 데이터, AI, 테스트 역량을 자연스럽게 보여주는가
- 개인 프로젝트 범위에서 완성하고 배포하고 시연할 수 있는가
- 사용자가 결과를 직접 확인할 수 있는 명확한 핵심 시나리오가 있는가

## 첫 회의의 산출물

1. 후보 문제 3개와 대상 사용자
2. 경쟁 서비스와 대체 행동 조사
3. 후보별 차별점, 구현 난이도, 포트폴리오 설명력 비교
4. 선택한 문제의 핵심 사용자 여정
5. MVP 범위와 명시적인 제외 범위
6. 자동 검증 가능한 완료 조건

이 결론이 승인되기 전에는 제품 코드를 만들지 않는다.
